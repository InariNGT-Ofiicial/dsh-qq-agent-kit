# 让 Agent 帮你把个人 QQ 接入 DSH

把完整源码包解压到固定目录，把下面的话交给能操作你电脑的 Agent：

> 请先阅读包内 AGENTS.md 和 docs/Agent执行手册.md，检查我的环境并执行个人 QQ 接入。先做本地私聊验证，再根据我的服务器条件上云。你负责执行脚本和排错；需要我提供信息、手机扫码或发送测试消息时，分步告诉我。不要覆盖已有部署。

你需要准备一个自己控制的 QQ 小号、登录该小号的手机，以及与小号互为好友的主号。模型需要可用的 DeepSeek 账号或 API Key；上云另需一台可通过 SSH 管理的 Linux x86_64 服务器。没有服务器也能先完成本地路线。

## 必做：告诉 Agent 你的选择

说明要做“本地接入”还是“本地验证后上云”，提供小号号码，并明确允许自动回复的私聊对象。已有 QQ、模型登录或 SSH 配置时，先让 Agent 查找，不必重新安装。密钥和密码在 Agent 指引的本机私密输入入口填写，不粘贴到聊天。

## 扫码确认：由你亲自操作

Agent 准备好登录页面后，用小号所在手机扫码，并核对手机显示的账号再确认。二维码过期让 Agent 刷新；不要反复扫旧图片。首次本地接入可能复用登录状态，上云或恢复登录可能再次要求手机验证。

之后按 Agent 给出的口令，从主号向小号发送一次配对消息。收到“私聊测试已配对”后，再发“你好”或“云端测试”，告诉 Agent 是否收到回复。配对口令只发到这一好友私聊。

## 故障恢复：把现象告诉 Agent

“二维码过期”“手机已确认但没有回复”“提示账号已登录”都可以直接反馈。Agent 应保留配置，先查登录、模型和桥接状态，再告诉你是否需要重新扫码；不要自行删除目录或重复安装。

本包已实际跑通本地和云端的单用户纯文本自动回复。每条消息是独立会话，不含人格、职务、工作内容、长期记忆或工具执行。服务可以开机启动，但 QQ 有时仍要求手机验证；安装和扫码时间不属于所谓“三秒接入”。
