# R4 独立部署执行记录

本次在原服务器新增 `~/dsh-qq-personal-lab`，保留原 `qqbot` 服务及 NapCat、AstrBot 容器。没有升级宿主全局 Node。当前执行结果以 `validation.json` 为准。

## 组件与隔离

- 私有 Node v24.21.0，下载官方 Linux x64 包并校验官方 SHASUMS256。
- 主项目和 vendor 分别 `npm ci --ignore-scripts`；云端8项回归测试通过。
- `dsh-qq-personal-model.service`：ubuntu用户，回环13080，MemoryMax=384M，独立DSH_HOME；真实模型调用通过。
- `dsh-qq-personal-bridge.service`：仅处理既有配对用户的私聊，MemoryMax=128M；协议端登录及账号检查通过后才启动。
- `dsh-qq-personal-napcat`：独立QQ状态目录和配置卷，512MiB内存上限，含交换上限768MiB，最多256个进程，不授予privileged、不挂载Docker socket。
- 容器内接口监听0.0.0.0，宿主只发布127.0.0.1上的13000、13001、16099。不要把容器内监听和宿主公网暴露混为一谈。

NapCat固定v4.18.41 amd64摘要：`sha256:69c5ca84ec226d658d0d5cd19997c6c89169da3206faa2948c2dc67d669b6406`。官方仓库连接超时后，核对Docker Hub官方标签的架构摘要与服务器已有镜像入口返回的摘要一致，再按digest拉取。不是直接信任镜像站的latest。

## 部署入口

先通过SSH把 `git archive` 的源码包展开到一个新的专用目录，运行 `scripts/install-cloud-runtime.sh`。它不修改全局Node，安装脚本被禁用。然后使用私有Node执行：

```bash
export PATH="$PWD/.runtime/node-v24.21.0-linux-x64/bin:$PATH"
node scripts/init-local.mjs <小号QQ号>
node scripts/setup-dsh.mjs
node scripts/setup-cloud-services.mjs
# 若用户授权复用服务器已有模型Key，可由管理员执行：
sudo "$PWD/.runtime/node-v24.21.0-linux-x64/bin/node" scripts/import-cloud-api-key.mjs <已有env文件>
# 将新生成的 .local/dsh-home/.env 归属改回服务用户，保持600权限。
sudo install -m 644 .local/systemd/*.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now dsh-qq-personal-model
node scripts/smoke-dsh.mjs
```

不得输出已有env文件，或把密钥放进命令行参数。这里仅复制DEEPSEEK_API_KEY这一个值到隔离home；不导入官方Bot AppSecret或角色配置。

已经完成本地配对时，使用私有文件仅迁移selfId及allowedPeers，通过 `import-pairing.mjs` 校验，不重配模型，不传输QQ缓存和接口令牌。云端接口令牌重新生成。

镜像下载完成后，`bash scripts/create-cloud-napcat.sh` 只创建指定名称的新容器，若重名则拒绝覆盖。随后 `sudo docker start dsh-qq-personal-napcat`。用 `napcat-login-status.mjs` 检查状态，`export-login-qr.mjs` 导出本地私有二维码文本交给账号持有人扫码。二维码不进入Git或公开包。

同一个小号切到云端前停止本机实验桥接和本次NapCat实例。扫码后先 `node scripts/probe.mjs` 核对账号匹配和在线，再启动 `sudo systemctl enable --now dsh-qq-personal-bridge`，由主号发新私聊验收。最后进行专用服务重启测试、重新核对真实私聊、原服务健康与内存；不能把云端模型调用通过等同于完整QQ链路通过。

## 回滚

```bash
sudo systemctl disable --now dsh-qq-personal-bridge dsh-qq-personal-model
sudo docker stop dsh-qq-personal-napcat
```

仅停本次专用服务，保留状态目录和镜像以便恢复，不停止原 `qqbot`、`napcat` 或 AstrBot。若回到本机，先停止云端小号实例，再按本地README启动；同号重复登录需要处理。

## 边界

2GiB宿主原本已使用交换空间；资源上限限制新实例影响，但不保证满载性能。当前只验收单用户短文本，尚不承诺长期无人值守、媒体消息、并发或生产SLA。原NapCat的公网绑定与旧鉴权问题列于预检文档，本次未擅自修改原系统。
