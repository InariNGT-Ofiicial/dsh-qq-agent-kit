# 分发后 Agent 的无账号云端演练

目的：从干净源码与独立运行时验证通用镜像构建、配置、管理页、二维码与重启；不登录已有在线 QQ，不把组件通过冒充真实私聊通过。

## 隔离前提

用全新的目录展开 Git 源码包；不要复制线上 `.local` 或 QQ 状态。检查资源、Docker 和端口23000/23001/23080/26099均空闲，且没有 `dsh-qq-rehearsal-napcat` 容器或同名模型服务。在线部署的名称、状态、启动时间及只读 probe 结果先留作比较。

演练默认使用 `dsh-qq-rehearsal` 实例名、10000端口偏移。占用时不要停止现有实例，应先调整演练命名与偏移。正式部署可在 init 后、setup-cloud-services 前执行 configure-cloud-instance.mjs 定制名称/偏移；初始化后已生成服务或已处理消息的实例拒绝改名。Agent 必须核实目录全新，不能把该入口用于迁移在线配置。

## 必做·Agent

```bash
bash scripts/install-cloud-runtime.sh
export PATH="$PWD/.runtime/node-v24.21.0-linux-x64/bin:$PATH"
bash scripts/build-cloud-image.sh
bash scripts/rehearse-cloud-image.sh
```

build 固定官方 amd64 摘要，只构建新镜像，不替换在线容器。大层下载慢不等于失败；查看进度和磁盘，不循环重启拉取。不更改 Docker daemon 全局代理或重启 Docker。必要时显式选择包含同一摘要的镜像源，不接受latest或其他摘要。

rehearse 脚本使用占位账号初始化后清空 autoLoginAccount，没有用户名单，不启动桥接，不安装systemd服务。它依次创建独立容器、核验WebUI鉴权与私有二维码、重启同一演练容器再核验，最后自动停止容器。演练容器restart策略为no，保留状态便于诊断。二维码文件仅存 `.local`，不得扫码或公开。

若演练失败，EXIT清理会停止已创建的演练容器。保留该目录检查，不把整个目录删掉重试，也不重复init。修复后手动启动同一个演练容器，重新执行 export-login-qr 与 login-status 检查，再停止；若需完整重跑，先确认并清理本次专属资源，另用全新目录。

若镜像下载期间需要先验证模型，可以先执行 `bash scripts/rehearse-cloud-image.sh --prepare-only`，完成模型测试后再以 `--resume` 继续镜像演练。resume只接受本包占位账号、空配对且禁用自动登录的配置，不会重置任何状态。

## 慢网络恢复：官方缓存转运

本轮官方直接拉取在超时窗口内未完成，镜像源的大层也很慢。远端Python访问DockerHub鉴权服务同样超时，因此只转运一个大层仍不足以完成恢复。最终在可信Windows工作站下载**完整官方清单、配置和所有层**，逐项验证大小和SHA，再经SSH上传；回环缓存恢复构建成功。

1. Windows执行 `scripts/fetch-official-image-cache.ps1 -CacheDirectory <私有工作目录>`。输出只有公开摘要。缓存约612 MB，不加入源码包。fetch-official-image-layer.ps1保留为单层下载辅助；本轮完整恢复使用cache脚本。
2. 通过已验证SSH将缓存文件上传到演练目录 `.runtime/registry-cache/`，不要上传用户配置。确认固定清单和全部blob齐全。只停止本次失败的拉取客户端，先核对PID和完整命令；不停止Docker daemon或容器。
3. 远端专用终端运行 `python3 scripts/official-registry-relay.py --cache .runtime/registry-cache --port 25000`。等到输出固定清单校验通过并已监听后，再进行下一步。它只监听127.0.0.1，只允许固定镜像的清单与blob，并再次校验内容；不开放公网。
4. 在另一远端终端执行：

```bash
NAPCAT_BASE_IMAGE=127.0.0.1:25000/mlikiowa/napcat-docker@sha256:69c5ca84ec226d658d0d5cd19997c6c89169da3206faa2948c2dc67d669b6406 bash scripts/build-cloud-image.sh
```

5. 构建完成停止本次relay进程，核对25000无监听；保留公开缓存供恢复。无需修改Docker全局代理、不关闭TLS校验、不使用其他版本的镜像。缓存是用户按许可自行下载的运行时，不随源码再分发。

## 模型组件的独立验证

容器演练停止后运行 setup-dsh，使用用户已授权模型Key的私密导入入口。安装生成的 `dsh-qq-rehearsal-model.service` 并临时启动，先运行 wait-dsh.mjs 再运行 inspect-dsh 与 smoke-dsh；不能固定sleep几秒便认定就绪。核验visibleTools=0，然后停止、禁用该演练模型服务，并按约定删除演练Key副本。无需启动桥接，无需登录QQ。实际Key禁止放入命令参数或公开日志。

注意专属模型端口为23080；setup-cloud-services 已从 config.dshUrl 读取，不再写死13080。每次新SSH会话重新设置私有Node PATH。
